# Public engineering samples

These are **public demonstration projects**, not claims of production deployment or commercial impact. Their repositories are the primary source of truth.

## 1. Log Anomaly Detector

**Repository:** [SkAdr1an/log-anomaly-detector](https://github.com/SkAdr1an/log-anomaly-detector)

**Problem explored:** how to analyze event logs and detect records that differ from expected patterns.

**Documented implementation:**
- Python and scikit-learn for anomaly-oriented analysis.
- CSV report exports and PNG visualizations.
- Synthetic example data to support reproducible experimentation.

**What it illustrates:** data-processing workflows, structured output and analytical prototyping.

**Boundaries:** the public documentation describes a demonstration project. It does not establish production accuracy, benchmark performance or deployment at customer scale.

## 2. HelpDesk Laravel

**Repository:** [SkAdr1an/helpdesk-laravel](https://github.com/SkAdr1an/helpdesk-laravel)

**Problem explored:** handling support tickets with user accounts and permission boundaries.

**Documented implementation:**
- Laravel 12, PHP 8.3, MVC, Blade, Tailwind and SQLite.
- Ticket creation, listing, viewing, editing and deletion.
- Authentication and user-scoped authorization.
- Form validation and protected routes.

**What it illustrates:** CRUD design, web application foundations, authentication and authorization concepts.

**Boundaries:** this is described by its repository as a technical learning exercise. It should not be presented as a deployed customer help desk.

## How I evaluate software work

For new projects, I prioritize the problem definition, scope, access control, data handling, test strategy and operational limitations. Public projects demonstrate code and experimentation; professional projects may also require approved case studies and measured outcomes.
